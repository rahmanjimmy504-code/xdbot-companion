**Scope:** independently improve the separate xdBot Companion, not publish a replacement or recovered xdBot source. The user authorized examining their `zilko.xdbot.geode`; do not upload that package, private macros, or website credentials with this source. ## Reproducible observations, not source recovery

- Authorized package: `zilko.xdbot.geode`, 13,429,656 bytes, SHA-256 `f5b0fab5d21ec2431b3c10fee5815a5711063c511314a8be2155f741f76c71fa`. REA 6.5.0's `inspect-artifact` (safe artifact graph) identified a ZIP root, **40 distinct nodes / 43 occurrences**, including two ELF libraries, one PE DLL and one Mach-O dylib. This is a static package inventory, not functional decompilation. The checked-in repository's main-branch `.geode` is a different 8,639,511-byte file (SHA-256 `e2e2572756384dbfacc45ea3b10bb340dafa1f2c47ed20d64d1f145199fd612a`); do not conflate that file with the user's 2.7.7 package.
- Android64 library: `zilko.xdbot.android64.so`, 11,989,144 bytes, SHA-256 `6cff9e049b7b5d7d0af755bfe5d2001f85272add711523183d1d98bada7691fd`. ELF header reports **AArch64** and a symbol table. `nm -C` finds `LoadMacroLayer::reloadList(int)`, `onImportMacro(...)`, `onImportMacroFinished(...)`, `onSelectAll(...)`, `SaveMacroLayer::onSave(...)`, `Macro::isGDR2Data(...)`, and `Macro::importGDR2(...)`. Static strings include `macros_folder`, `.gdr`, `.gdr.json`, `.gdr2`, and `.cml`. These identify names/features in the compiled build; they do not reveal complete control flow, file validity, screen geometry or runtime behavior.
- REA `inspect-pe-resources` on `zilko.xdbot.dll` (SHA-256 `8252391a4abd9efec83a06b2a7320236e189aa20e7d8b49d26dbf358d2d0126e`) reports PE32+ x64, one type-24 resource and **no icon groups**. It is not evidence that the mod lacks all other images (they may be packaged elsewhere).
- REA `doctor --provider ghidra` reports `GHIDRA_INSTALL_DIR is not set`. Its offline `inspect-binary-layout` docs claim initial real verification for **ELF x86-64**, not this ARM64 binary. No Ghidra/IDA/Hopper decompilation, function cross-references, ARM64 layout inference, emulator run, phone test or complete xdBot recreation was performed. A static symbol is not original source code. No xdBot binary/assets/pseudocode are included in this companion source.

## Independent improvements and cautious suggestions

1. **Separate companion, implemented in beta.15 source:** share preflight now rechecks every selected path using the same metadata/name/size rules as local export. The observed macro filename families inform the extension allowlist. This blocks accidental sharing of empty/unrelated files if a selection changed after listing; it does **not** parse file contents or prove a replay is valid.
2. **Separate companion, implemented in beta.15 source:** an Android document picked manually for HYPE now gets a companion-owned ATTACH/CANCEL prompt after choosing it. A preselected `.gdr` or `.gdr.json` retains its existing prompt. `.cml`/`.gdr2` remain local-export/share-only, not HYPE uploads. The website may process a file as soon as it is attached. No credentials are copied or sent by the companion itself.
3. **Proposal for xdBot maintainers, not an xdBot patch or established deficiency:** document the format/version matrix for `.gdr`, `.gdr.json`, `.gdr2`, `.cml` and import failures, and expose a public, stable extension point for companion buttons near Load Macro controls. The binary shows relevant format/import functions, but their UI feedback and whether such an extension point already exists were **not** established.
4. **Further investigation:** configure a supported Ghidra provider and inspect narrowly scoped Android64 functions in REA, review licensing/permission before any broader reconstruction, then verify changes with a disposable macro on an Android device. Avoid copying recovered xdBot code or art. Beta.15 has local host/Java/D8 checks only; it still needs a fresh native CI build and phone test.
