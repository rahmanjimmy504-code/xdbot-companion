# Developer source candidate — do not publish as a release

Beta.3 successfully compiled in GitHub Actions on Android32, Android64, Windows x64 and iOS arm64, but device behavior is untested. The new beta.4 one-file EXPORT feature is only a source candidate and has not passed four-platform CI; Android export deliberately fails closed because the Geode launcher loses the save URI. Users can use the existing SHARE action with a Files app on Android.

Apply the supplied beta.4 source ZIP **into the existing `port-preview` branch**, not the release branch. In a Codespace on the current `port-preview` branch: upload the ZIP, run `git pull --ff-only`, then `unzip -oq <ZIP-name> && rm <ZIP-name> && git add -A && git commit -m "Prototype native local macro export" && git push`. If the push alone fails, resolve its GitHub authorization and push the already-created commit; do not re-extract/recommit. Always check the exact ZIP filename first.

Wait for **all** CI jobs and the combine job to pass on the new commit before downloading the latest artifact. A green build still does not establish that Android's SAF destination is writable or that iOS, Windows and Android pickers and xdBot UI work in the game. Test a single .gdr, old .cml and new .gdr2 file, cancellation, repeated taps, choosing the original path, Downloads/Files, and verifying actual saved bytes in the target app. Do not publish the generated package or label Hyperbolus sign-in/account downloads as implemented. The earlier human review requirement remains.
