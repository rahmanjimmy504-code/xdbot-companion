# xdBot Companion — Android64 HYPE + GDB developer source (beta.13)

**Source candidate, not an installable Geode mod or public release.** A separate, opt-in add-on by Jimmy_1234ha; xdBot's own binary/UI are not modified. Android64 is the first website target. Android32, Windows x64 and iOS arm64 website views are pending; native Linux/macOS are out of scope.

## UI and websites

- The companion macro popup has a **HYPE** button for https://hyperbolus.net/ and a **GDB** button for https://gdbrowser.com/. Each launches a separate native Android WebView Dialog *inside* Geometry Dash. Beta.9's GD Browser view opened on the Fire tablet, but its narrow dialog triggered the site's own landscape-width warning. Beta.10 makes only the GDB dialog 94% of the screen width and adjusts its wide viewport; the proposed fix requires a phone retest. Buttons within each dialog switch to the other website, closing the previous WebView. Both sites have regular in-page text/forms and same-site HTTPS navigation; external main-frame links are blocked. Do not assume that every external redirect or site-specific feature will work until tested.
- All **14 icons are individually image-generated** as bold, colourful arcade-game UI sprites inspired by Geometry Dash menu aesthetics, with no existing game artwork copied. Their full-size originals are in `art/source-icons/`; `scripts/create-icons.py` removes the plain white background and builds separate **96px transparent PNGs** in `resources/icons/`. Unlike beta.11's framed pictures and beta.12's programmatically drawn glyphs, these are generated, isolated icon silhouettes. The native panel enlarges them, spaces list symbols and filenames farther apart, and shows five rows per page. Actual screen fit remains untested. The picker uses only its own UI children, never the old crash-inducing `dynamic_cast` scan of xdBot children.
- Hyperbolus's own website hosts email/password login. The add-on does not make or store a separate password field. A selected `.gdr` or `.gdr.json` can be offered only at the Hyperbolus replay-upload page after explicit confirmation; the website requires its own Submit action. `.cml` and `.gdr2` are rejected for Hyperbolus uploads, but remain eligible for **local** macro export. The native SAF document picker supports manual file attachment and account downloads to the user-chosen URI.
- **GD Browser receives no companion-preselected macro.** Its own forms work; if it requests a file, the companion first asks permission, then Android's document picker lets the user choose it. The website may process it upon selection; do not assume the site's own form waits for a separate submit. Its downloads use the same URI-based save picker. No site cookies are forwarded to off-site redirect hosts.
- SHARE remains the existing multi-macro Android system chooser. Local EXPORT of one macro stays URI-based; no guessed filesystem path is used.

## Verification status

Beta.8 was phone-confirmed on the user's Fire tablet for Hyperbolus window opening, website text input and local EXPORT after enabling the tablet's Amazon System WebView. Account download and end-to-end upload were **not** verified: Hyperbolus's public level page for ID `15031583` independently returned `400 Level could not be fetched`, before a macro could be validated. Do not substitute an unrelated Level ID. Beta.9 native CI and the 14-icon packaging check succeeded in run 38952606461; the Fire tablet showed the icons were tiny and GDB's dialog was too narrow. Beta.10 Java/D8 compilation and local policy tests pass; beta.11's phone-test repack reuses the beta.9 native binary and was reported too small and too picture-like. Beta.12 passed Android64 CI at run 38957198424, but the user requested another revision with independently generated artwork and larger UI. Beta.13 changes the native C++ popup geometry and all 14 PNG resources. **A new Android64 CI native build is mandatory; there is no installable beta.13 package yet.** GDB width and final icon appearance remain unverified on a tablet. Do not submit credentials/private macros to the project. Browser cookies belong to Android's WebView, not a Chrome session. Process-death restoration while a document picker is open also needs review.

## Build route

Push this source (without the outer source ZIP) to the separate `hyperbolus-android` branch. `.github/workflows/hyperbolus-android.yml` builds only Android64, verifies its native ELF, Java DEX and 14 enlarged icon resources, and uploads `DEV-HYPE-GDB-ANDROID64-beta.13-UNREVIEWED`. It does not publish a release. `scripts/build-hyperbolus-bridge.sh` compiles the Java bridge against the Android SDK and D8; no AndroidX activity-result classes are packaged because the released Geode launcher obfuscates those names. The companion uses the Android framework Fragment for document results. Geode CLI **flattens `resources.files` to filenames**; PNG icons are declared under `resources.folders` instead so the runtime `icons/` directory survives packaging. The folder declaration was confirmed by successful beta.9 CI run 38952606461. For beta.13, a new CI build is required because `MacroPicker.cpp` and `MacroPicker.hpp` changed again. **Do not install any older repack as beta.13.** Verify the actual beta.13 CI artifact and test on a phone before calling the icon size or GDB layout fixed.
