# xdBot Companion — Android64 beta.19 AI pause-menu start correction

**Beta.19 source only; no beta.19 native build or device test.** Beta.18 built in Actions run 39454823825 and its in-level START AI button appeared on the user's device, but confirming it produced a generic "AI could not start" popup. A stale-session check could reject a restart after a cancelled attempt; the generic error did not identify the exact cause on this device. Beta.19 removes the fragile check, gives precise start-failure reasons, and moves the single AI control to the **Pause menu**, as requested. No gameplay overlay remains. Pause a disposable classic level, tap START AI, confirm, then tap RESUME to reset and begin. This is a new independent button, **not** the removed XD TOOLS panel. The Geode setting remains OFF by default and cancellations do not automatically toggle it. UI and AI runtime behavior are **not yet beta.19 phone-verified**. The opt-in Android gameplay adapter now proposes bounded jump inputs, observes deaths and completion, requests a repeat run, and writes a local legacy `.gdr.json` candidate only if both completions match. This is *not* a trained general AI, cannot promise to solve any level, and its xdBot 2.7.7 import/playback has **not** been verified. See `AI-RECORD-ANDROID64-STATUS.md` before attempting a device test. The old XD TOOLS pause panel and companion FPS/deaths monitor remain removed.

**Source candidate, not an installable Geode mod or public release.** A separate, opt-in add-on by Jimmy_1234ha; xdBot's own binary/UI are not modified. Android64 is the first website target. Android32, Windows x64 and iOS arm64 website views are pending; native Linux/macOS are out of scope.

## UI and websites

- Beta.14 and beta.15 remove the separate **XD TOOLS** pause-menu entry and the companion's FPS/deaths/last-death monitor entirely. Open the picker only through the companion-owned **SHARE MACROS** button alongside xdBot's macro controls. xdBot itself, its macros, and its other menus are untouched. This simplification requires a fresh native build and phone test.
- The companion macro popup has a **HYPE** button for https://hyperbolus.net/ and a **GDB** button for https://gdbrowser.com/. Each launches a separate native Android WebView Dialog *inside* Geometry Dash. Beta.9's GD Browser view opened on the Fire tablet, but its narrow dialog triggered the site's own landscape-width warning. Beta.10 makes only the GDB dialog 94% of the screen width and adjusts its wide viewport; the proposed fix requires a phone retest. Buttons within each dialog switch to the other website, closing the previous WebView. Both sites have regular in-page text/forms and same-site HTTPS navigation; external main-frame links are blocked. Do not assume that every external redirect or site-specific feature will work until tested.
- All **14 icons are individually image-generated** as bold, colourful arcade-game UI sprites inspired by Geometry Dash menu aesthetics, with no existing game artwork copied. Their full-size originals are in `art/source-icons/`; `scripts/create-icons.py` removes the plain white background and builds separate **96px transparent PNGs** in `resources/icons/`. Unlike beta.11's framed pictures and beta.12's programmatically drawn glyphs, these are generated, isolated icon silhouettes. The native panel enlarges them, spaces list symbols and filenames farther apart, and shows five rows per page. Actual screen fit remains untested. The picker uses only its own UI children, never the old crash-inducing `dynamic_cast` scan of xdBot children.
- Hyperbolus's own website hosts email/password login. The add-on does not make or store a separate password field. A selected `.gdr` or `.gdr.json` can be offered only at the Hyperbolus replay-upload page after explicit confirmation; the site also presents its own upload form, but a website may process an attachment immediately, so do not treat its Submit as the only transfer point. `.cml` and `.gdr2` are rejected for Hyperbolus uploads, but remain eligible for **local** macro export. Manual SAF file attachment asks an additional ATTACH/CANCEL confirmation after a user picks a HYPE replay; the site may process the file immediately when attached. The native SAF document picker supports manual file attachment and account downloads to the user-chosen URI.
- **GD Browser receives no companion-preselected macro.** Its own forms work; if it requests a file, the companion first asks permission, then Android's document picker lets the user choose it. The website may process it upon selection; do not assume the site's own form waits for a separate submit. Its downloads use the same URI-based save picker. No site cookies are forwarded to off-site redirect hosts.
- SHARE remains the existing multi-macro Android system chooser. Local EXPORT of one macro stays URI-based; no guessed filesystem path is used.

Do not submit credentials/private macros to the project. Browser cookies belong to Android's WebView, not a Chrome session. Process-death restoration while a document picker is open also needs review.

## Build route

Push this source (without the outer source ZIP) to the separate `hyperbolus-android` branch. `.github/workflows/hyperbolus-android.yml` builds only Android64, verifies its native ELF, Java DEX and 14 enlarged icon resources, and uploads `DEV-HYPE-GDB-AI-ANDROID64-beta.19-UNREVIEWED`. It does not publish a release. `scripts/build-hyperbolus-bridge.sh` compiles the Java bridge against the Android SDK and D8; no AndroidX activity-result classes are packaged because the released Geode launcher obfuscates those names. The companion uses the Android framework Fragment for document results. Geode CLI **flattens `resources.files` to filenames**; PNG icons are declared under `resources.folders` instead so the runtime `icons/` directory survives packaging. The folder declaration was confirmed by successful beta.9 CI run 38952606461. Beta.18 compiled but its START AI produced a generic start failure on device. A **new beta.19 CI build** is required for the Pause-menu hook and diagnostic path. **Do not relabel beta.18 as beta.19.** Verify SHARE MACROS remains and the old XD TOOLS panel/monitor are absent. Android64 beta.19 native CI and on-device checks are pending.
